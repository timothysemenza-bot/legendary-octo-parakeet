# Crawford Proposal Operations Modernization

## Slide 1: Title And Thesis

- Headline: `Proposal operations modernization for more reliable automation-readiness`
- Subhead: Boss Key as an operator-builder partner for strengthening the full growth-to-proposal chain
- Key points:
  - This is not a boilerplate refresh
  - This is not automation for its own sake
  - The objective is disciplined proposal operations, governed reusable knowledge objects, and selective automation where inputs are strong
- Visual cue: simple chain graphic from qualification to proposal execution

## Slide 2: Where Proposal Automation Usually Breaks

- Headline: `Most automation struggles start upstream`
- Key points:
  - opportunities enter without enough strategy behind them
  - proposal engages too late
  - pricing support arrives under compression
  - executives get pulled into fire drills
  - reusable content is not consistently trustworthy
  - teams rebuild because source content is not governed
- Visual cue: friction map or horizontal workflow with breakpoints highlighted

## Slide 3: The Strategic Contrast

- Headline: `Document-fragment reuse is not the same as operating-model-driven reuse`
- Key points:
  - Qvidian-style reuse often centers on fragments pulled from large libraries
  - fragments lose value when ownership, recency, and business context are weak
  - Boss Key's model focuses on current, owner-backed reusable knowledge objects
  - automation becomes more reliable when retrieval is grounded in governed source content
- Visual cue: two-column comparison graphic labeled `fragment reuse` vs `governed reuse`

## Slide 4: Boss Key Proposal Operations Model

- Headline: `Three linked layers`
- Key points:
  - Operating Layer: qualification, intake, role clarity, kickoff discipline, review cadence, escalation paths
  - Knowledge Layer: inventory, repository architecture, taxonomy, source-of-truth mapping, ownership, stale-content control
  - Automation Layer: retrieval-ready modules, governed repository approach, structured prompts and templates, human-in-the-loop review
  - automation is the result of stronger inputs, not the first move
- Visual cue: three-layer stack diagram

## Slide 5: Proposed Engagement Structure

- Headline: `A phased modernization path`
- Key points:
  - Phase 1: Diagnostic
  - Phase 2: Operating-Model Design
  - Phase 3: Repository and Governance Build
  - Phase 4: Automation Enablement Pilot
  - Phase 5: Stabilization / O&M
  - each phase produces practical working artifacts, not abstract recommendations
- Visual cue: five-phase timeline with short outcome labels

## Slide 6: Before / After Operating Shift

- Headline: `What changes in practice`
- Key points:
  - boilerplate reuse becomes governed reusable content objects
  - reactive bid response becomes earlier qualification and capture discipline
  - ad hoc SME requests become structured intake and ownership
  - last-minute executive reviews become predefined checkpoints
  - automation on bad inputs becomes automation on governed inputs
- Visual cue: before/after table with five rows

## Slide 7: Recommended Pilot

- Headline: `Start with one business line or pursuit segment`
- Key points:
  - use a focused pilot to test content trustworthiness, repository structure, intake discipline, and automation feasibility
  - measure cycle-time improvement, draft quality, review burden, and confidence in reusable content
  - use the pilot to decide what should be standardized, governed, and automated next
  - keep the starting point low-risk and evidence-driven
- Visual cue: pilot scorecard showing trustworthiness, readiness, and measured outcomes
