# Knowledge Harvest

## Immediate lessons

1. The kickoff package should not be scheduled until the first-pass requirements baseline exists.
2. Transition claims need proof points earlier than the team expected.
3. Review comments are much easier to act on when they are consolidated by section owner and priority.

## Reusable assets to keep

- a healthcare-transition milestone checklist
- a patient-facing training proof-point library
- a short review issue-log template for red reviews

## Recommended repository updates

- add a reusable transition-plan skeleton to the proposal template library
- add a standard field in the kickoff packet for proof-point sourcing
- add a lessons-learned prompt for post-review and post-submission runs

## Next-run improvements

- ask for past performance candidates before kickoff
- require one accountable owner per long-lead item
- trigger a knowledge-harvest run after every major review checkpoint, not just after submission
