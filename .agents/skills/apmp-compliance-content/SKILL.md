# APMP Compliance Content

## Purpose

Convert customer requirements and pursuit strategy into a controlled content-design package before or during drafting.

## When to use it

- when requirements need to be shredded and baselined
- when the compliance matrix or response matrix is missing or stale
- when writers need an annotated outline or section content plans
- when a recurring run should improve compliance and responsiveness without rewriting the full proposal

## Required inputs

- solicitation, notes, or other requirement source material
- any current outline, compliance matrix, or draft sections
- known win themes, discriminators, or executive-summary direction
- page, word, or structure constraints if known

## Expected outputs

- requirements baseline
- compliance matrix or response matrix starter
- annotated outline
- section content-plan guidance for critical sections

## Step-by-step instructions

1. Read `docs/apmp-automation-reference-map.md`, then use the requirements, compliance-matrix, and content-plans sources listed there.
2. Strip explicit and implied requirements into discrete items. Keep the customer’s order, numbering, and language whenever possible.
3. Build or update the compliance matrix early, not after drafting. Use it as the planning backbone.
4. Translate the matrix into an outline and author guidance. Add themes, proof points, graphics, page budgets, and other section notes only where they help execution.
5. Use just-enough detail. High-value or high-risk sections deserve fuller content plans; low-risk sections can stay at annotated-outline level.
6. Preserve responsiveness, not just compliance. Call out hidden needs, disqualifiers, and places where benefits or proof need to be clearer.
7. End with the next handoff: kickoff package refinement, draft writing, or review-cycle preparation.
