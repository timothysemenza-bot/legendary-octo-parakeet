## Homepage structure mapped to 6-part proposal logic

### 1) Executive Summary (above the fold)
- Objective: establish problem, promised outcome, and founder credibility in <10 seconds.
- Key message: Boss Key installs operating discipline that protects margin and execution reliability.
- Proof elements: founder experience line + quick “supported teams like…” signal.
- CTA: `Book a diagnostic`.

### 2) Problem Definition
- Objective: help buyer self-identify quickly.
- Key message: operational friction is creating margin leakage, team drag, and inconsistent delivery.
- Proof elements: pain list stated in buyer language.
- CTA: jump to diagnostic.

### 3) Solution Framing
- Objective: explain operating model without tool hype.
- Key message: assess -> stabilize -> install leadership cadence.
- Proof elements: clear 3-step approach and what changes in 30-60 days.
- CTA: request diagnostic to map current-state issues.

### 4) Proof / Credibility
- Objective: reduce perceived delivery risk.
- Key message: prior operating experience and repeatable execution model.
- Proof elements:
  - 2-3 testimonial placeholders
  - “Who I’ve supported” placeholder list
  - 2 case-study placeholders (problem, intervention, observed shift without fabricated metrics)
- CTA: review services and book diagnostic.

### 5) Engagement Model
- Objective: clarify timeline, scope boundaries, and working rhythm.
- Key message: diagnostic first, then focused sprint, then optional ongoing operating support.
- Proof elements: included vs excluded list, FAQ pricing philosophy.
- CTA: book diagnostic.

### 6) Next Steps CTA
- Objective: make first step low-friction and explicit.
- Key message: conversation -> diagnostic -> engagement decision.
- Proof elements: simple contact form + scheduling option.
- CTA: `Book a diagnostic` and `Request a diagnostic` (form submit).

## CTA and conversion rules
- Primary CTA label everywhere: `Book a diagnostic`.
- Secondary CTA label for form submissions: `Request a diagnostic`.
- All top-level CTAs should route to existing schedule URL if configured in code.
- Contact form fields: name, email, company, what you’re trying to fix.
