# Changelog

## 2026-03-04

### Proposal-first repositioning of BossKeyOps.com
- Reworked `boss-key-website/index.html` from a service brochure layout to a proposal-style narrative flow.
- Why: improve conversion by matching buyer decision logic (problem -> outcomes -> method -> proof -> engagement -> next step).

### New information architecture support
- Added `boss-key-website/services.html` for detailed engagement models and scope boundaries.
- Why: keep homepage concise while giving buyers enough depth to qualify fit.

### Copy and CTA standardization
- Replaced homepage copy to be outcome-first and judgment-led, with AI/automation treated as optional detail.
- Standardized CTA language to `Book a diagnostic` and `Request a diagnostic`.
- Why: reduce friction and clarify the first step.

### Proof scaffolding added (non-fabricated placeholders)
- Added structured placeholders for testimonials, supported organizations, and case studies.
- Why: provide clear spots for risk-reducing proof without inventing claims.

### Contact conversion updates
- Added short diagnostic form with required fields: name, email, company, what you are trying to fix.
- Kept scheduling behavior linked to existing calendar URL fallback already present in site code.
- Why: provide both high-intent booking and low-friction request paths.

### Documentation deliverables added
- Added:
  - `docs/site-audit.md`
  - `docs/site-plan.md`
  - `docs/copy-home.md`
  - `docs/copy-services.md`
  - `docs/changelog.md`
